# 第2章 计算机系统基础知识 — 学习笔记

> 学习目标：理论支撑实践，非应试导向。本章覆盖硬件、操作系统、数据库、网络、计算机语言、系统工程等基础学科，重点记录对架构设计有实际迁移价值的部分。

## 一、核心概念

### 1. 存储器分层结构
- **核心矛盾**：速度快、容量大、成本低不可兼得 → 用分层组合解决
- **分层**：寄存器 → 片上Cache(L1/L2) → 片外Cache(L3) → 主存(DRAM) → 外存(磁盘/SSD)
- **支撑理论——局部性原理**：
  - 时间局部性：刚访问过的数据大概率再被访问
  - 空间局部性：被访问数据附近的数据大概率也被访问
- **平均访问时间公式**：`平均时间 = 命中率 × 上层访问时间 + (1-命中率) × 下层访问时间`
- **实践映射**：CDN、多级缓存架构、数据库Buffer Pool设计，本质都是这套分层逻辑的复用

### 2. CISC vs RISC
- CISC（Intel/AMD x86）：一条指令做更多事，译码复杂
- RISC（ARM/Power）：指令精简、执行效率高，是现代指令集主流趋势

### 3. 操作系统核心机制
- **进程 vs 线程**：进程是**资源分配**的基本单位，线程是**CPU调度**的基本单位
- **分页 vs 分段**：分页是物理上的等长划分（对用户透明）；分段是逻辑上按功能划分（对用户可见，如代码段/数据段）
- **死锁四个必要条件**：互斥、请求保持、不可剥夺、循环等待
- **调度算法**：FCFS、SJF、时间片轮转、优先级调度、多级反馈队列

### 4. 数据库基础（详细内容见第6章）
- 三级模式：外模式（用户视图）— 概念模式（全局逻辑结构）— 内模式（物理存储）
- 3NF：消除非主属性对主键的传递依赖，减少数据冗余和更新异常
- ACID：事务的原子性、一致性、隔离性、持久性

### 5. 网络分层模型
- **OSI七层**（理论）：物理层→数据链路层→网络层→传输层→会话层→表示层→应用层
- **TCP/IP四层**（实际）：网络接口层→网际层→传输层→应用层
- **对应关系**：OSI的应用/表示/会话三层 → TCP/IP应用层（合并）；其余基本一一对应
- **排障思路**：DNS问题→应用层；连接/端口问题→传输层；路由不通→网际层；物理链路问题→网络接口层

### 6. 网络设备与工作层级
| 设备 | 工作层级 | 核心能力 |
|---|---|---|
| 集线器/中继器 | 物理层 | 纯信号广播/放大 |
| 网桥/交换机 | 数据链路层 | 基于MAC地址学习+精准转发 |
| 路由器 | 网络层 | 基于IP和路由表跨网络转发 |
| 防火墙 | 可跨多层 | 基于规则过滤，现代产品可做到应用层检测 |

### 7. 交换机原理
- **MAC地址学习机制**：记录源MAC与端口映射 → 查表转发 → 查不到则泛洪 → 定期老化更新
- **环路问题**：多链路提高冗余的同时会产生环路 → 用**生成树协议(STP)**阻塞多余路径，主链路故障时自动切换
- **VLAN**：物理网络逻辑隔离成多个广播域，用于不同用途设备的隔离（应用/数据库/办公网分离）

### 8. 路由器原理
- 工作在网络层，靠**路由表**决定下一跳，可静态配置或动态生成
- **路由协议分类**：
  - 内部网关协议(IGP)：组织内部用，又分两条技术路线——
    - 距离矢量协议：只知道"到某网络几跳"，简单但大网络易出问题
    - 链路状态协议（如OSPF）：全局拓扑视图，自己算最短路径，适合大规模网络
  - 外部网关协议(EGP)：组织之间用，BGP是事实标准，支撑起整个互联网的互通
- **实践映射**：云VPC的public/private子网+路由表+NAT网关，是这套理论的云化实现

### 9. 通信技术：复用技术
- TDM（时分复用）/ FDM（频分复用）/ CDM（码分复用）：解决"一条物理信道同时服务多路数据"的问题
- 软件层面的同源思想：HTTP/2多路复用、数据库连接池、CPU超线程

### 10. 网络工程：架构师的实际主导环节
- 三阶段：网络规划（需求驱动）→ 网络设计（总体目标/子网设计/设备选型/安全设计）→ 网络实施
- **地址规划**：结构化分层编址 → 让路由表收敛，减少路由条目（与分库分片键设计、微服务命名空间设计同源思路）
- **路由协议选择**：按规模匹配（小规模用距离矢量，大规模用链路状态，跨组织用BGP）——与服务发现机制的选型逻辑相通

### 11. 计算机语言分类
- 演化路线：机器语言（二进制，执行快但难写）→ 汇编语言（助记符，仍绑定硬件）→ 高级语言（可移植，效率优先）
- 建模语言：UML（4+1视图：逻辑/开发/进程/物理/场景视图）
- 形式化语言/方法：用数学符号（集合论、一阶谓词逻辑）消除需求描述的二义性
  - 代表：Z语言、VDM（维也纳开发方法）、CSP/CCS（并发行为描述，Go语言的CSP并发模型即源于此）
  - 适用场景：航空航天、核电站控制、芯片验证等高可靠性领域，主流商业软件开发较少用

### 12. 系统工程生命周期（7阶段）
探索性研究 → 概念 → 开发 → 生产 → 使用 → 保障 → 退役
- 比软件SDLC前面多"探索性研究/概念"阶段，后面多"生产/退役"阶段
- **退役规划要在概念阶段就想清楚**——技术选型时应同步考虑未来的下线/迁移路径

### 13. MBSE（基于模型的系统工程）
- 核心转变：从**文档驱动**（多份文档人工维护一致性）→ **模型驱动**（单一模型作为唯一事实来源，各视图自动派生）
- 三大支柱：建模语言（SysML）、建模工具、建模思路（方法论）
- 与现代实践的同构关系：本质思想与Infrastructure as Code / GitOps一致——都是用"模型/代码"取代"文档"作为唯一事实来源

### 14. RASIS
可靠性(Reliability)、可用性(Availability)、可维护性(Serviceability)、完整性和安全性(Integrity & Security)——评价系统健康度的通用框架，第8章质量属性会展开。

## 二、易混淆 / 易错点

1. **进程 vs 线程**：进程=资源分配单位，线程=调度单位——不要用"占不占内存"来区分
2. **分页 vs 分段**：分页是物理概念（等长、对用户透明），分段是逻辑概念（不等长、用户可见）——常被反着记
3. **OSI七层 ≠ TCP/IP四层的简单裁剪**：不是砍掉了三层，而是应用/表示/会话三层的功能被**合并**进了TCP/IP的应用层，实际协议栈里这三层没有独立实现
4. **交换机 vs 路由器**：交换机解决"同网络内精准转发"（数据链路层，靠MAC），路由器解决"跨网络转发"（网络层，靠IP）——不要混用"转发"这个笼统说法
5. **距离矢量 vs 链路状态路由协议**：距离矢量只知道邻居信息（局部视角），链路状态掌握全局拓扑（全局视角）——不是"新旧"关系，是适用规模不同
6. **静态路由 vs 动态路由协议**：静态是人工配置，动态路由协议（如OSPF/BGP）是路由器自动学习和更新——路由协议本身是"动态路由"的实现手段，不要把两者对立成互斥概念
7. **软件生命周期 vs 系统工程生命周期**：系统工程生命周期范围更大，包含软件生命周期之外的"探索性研究"和"退役"阶段
8. **形式化方法 ≠ 建模语言（UML）**：UML是半形式化的可视化建模语言，Z语言/VDM等形式化语言有严格数学语义，可以做正确性证明，两者定位不同不要混为一谈
