# 第3章 信息系统基础知识 — 学习笔记

> 本章是"企业信息系统"的分类学与商业视角，非硬核技术内容。核心价值：判断系统属于哪一类，决定了它的关键质量属性该往哪个方向设计。

---

## 一、核心概念

### 1. 信息系统的5个基本功能
输入、存储、处理、输出、控制 —— 判断任何信息系统"缺了哪块"的通用检查清单

### 2. 信息系统金字塔（对应组织三层级）
- **TPS（业务处理系统）— 操作层**：处理高频固定规则的事务（下单、记账）。核心诉求：事务一致性 + 高吞吐
- **MIS（管理信息系统）— 管理层**：汇总TPS数据辅助管理。分**开环**（批处理，事后生成报表）和**闭环**（实时反馈进决策过程）两种模式，选型时不要给开环需求上实时架构
- **DSS（决策支持系统）— 战略层**：提供模型/假设分析(what-if)辅助非结构化决策，比MIS多一层"可交互模拟"能力

### 3. 两个横向专项系统
- **ES（专家系统）**：把领域专家经验编码为可推理的规则/知识库
- **OAS（办公自动化系统）**：面向日常办公协同（审批流、公文流转）

### 4. ERP：横向打通，而非纵向分层
从MRP-II（制造业物料需求计划）发展而来，把企业内部各职能部门打通，再扩展到跨企业供应链协同。解决的是"信息孤岛"问题，与现代"中台"、跨部门数据打通诉求同源。

### 5. 数字化成熟度阶梯（通用框架）
电子政务四阶段模型：**起步（单向发布）→ 单向互动 → 双向互动 → 网上事务处理（完整闭环）**
可直接套用评估任何组织的数字化转型程度，与诺兰模型六阶段、企业信息化"局部到全局"演进逻辑本质相通。

### 6. 信息系统开发方法（简要，详见第5章软件工程）
结构化方法（适合业务稳定成熟场景）、原型法（适合需求不清晰场景）、面向对象方法（适合复杂多变领域）

## 二、易混淆 / 易错点

1. **TPS/MIS/DSS 不是三选一，是纵向分层关系**：DSS通常建立在MIS之上，MIS建立在TPS数据之上，不要把三者当作互斥的并列分类
2. **MIS开环 vs 闭环 ≠ 系统好坏之分**：只是匹配不同业务场景，闭环不天然比开环"高级"，选型看业务是否需要实时反馈
3. **ERP不是MIS的升级版**：ERP的扩展方向是"横向打通多部门/多企业"，MIS/DSS的扩展方向是"纵向支持更高层决策"，两条线不是同一个演化路径
4. **信息化 ≠ 单纯上系统**：企业信息化强调的是技术、管理、制度三方面同步创新，只买软件不改流程不算真正的信息化
