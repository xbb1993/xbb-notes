# 第17章 通信系统架构设计理论与实践 —— 学习笔记

> 定位：本章与日常开发工作关联度中等偏低，具体的路由协议实现、5G网元协议细节属于电信/网络工程专业范畴。但**层次化网络设计模型**（核心层/汇聚层/接入层的分层职责思想）和**5G服务化架构/网络切片**（服务化+多租户隔离思想在电信网络的印证）值得认真理解——这两块的设计哲学与你熟悉的软件分层架构、微服务、多租户隔离设计是同构的。5G具体网元协议、物理层技术等纯电信工程细节从简记录。

## 一、核心概念

### 1. 通信系统与5种常用网络架构

通信系统利用通信线路把地理分散的、具有独立功能的计算机系统和通信设备连接起来，依靠网络软件和通信协议实现资源共享和信息传递。5种常用网络架构：局域网、广域网、城域网、移动通信网、（存储网络）——不需要记每种的具体组网协议，重点在于理解不同网络规模对应不同的架构设计考量。

### 2. 层次化网络设计模型（本章最有迁移价值的部分）

**三层模型：核心层 - 汇聚层 - 接入层**

- **核心层**：网络互连枢纽，需用冗余机制保证高可用；**功能设计要"做减法"**——避免数据包过滤、策略路由等处理开销大的特性以降低时延；覆盖范围和连接设备不宜过多，保证良好可管理性；功能不宜多样化，避免降低性能
- **汇聚层**：承担安全访问控制、核心层流量控制；**关键职责是屏蔽细节**——接入层的子网划分对核心层透明（只上报汇聚后的大子网信息），核心层的全貌对接入层也透明（只宣告默认路由）
- **接入层**：为终端设备提供本地网段接入能力，负责用户管理（地址认证、用户认证等）

**层次化设计的三个优点**：①成本最低（各层只考虑自身功能和运维需求，避免不必要特性的额外花费）②可利用成熟模块化设备（避免不必要开发费用，利于稳定运行）③需求变化时更容易演化（某层改造不牵连其他层）

**与软件架构设计的同构关系**：
- 核心层"做减法、保持功能单一"≈ 核心交易链路/网关层不该堆砌复杂业务逻辑
- 汇聚层"细节屏蔽"≈ API网关、DDD防腐层（ACL）——上层不需要知道下层实现细节，只需稳定抽象接口
- 三层分工避免"牵一发动全身"≈ 第13章层次式架构的关注点分离原则

本质：把系统按职责切分成粗粒度的层，每层内部做减法保持单一职责，层与层之间通过屏蔽细节降低耦合——这是分层设计的通用工程哲学在不同领域的应用。

### 3. 网络工程三阶段方法论

网络规划（需求驱动+可行性分析+现有网络分析）→ 网络设计（总体目标/设计原则/子网设计/设备选型/安全设计）→ 网络实施（采购/安装/调试/切换/培训）。对应软件项目的"需求调研→详细设计→开发落地上线"节奏，提醒即使是基础设施建设也需要规范的项目管理节奏。

### 4. 网络安全设计要点

- **访问控制**：认证、控制策略实现、审计三环节；模型有自主型/强制型/基于角色/基于任务/基于对象等（与第4章信息安全基础知识交叉）
- **网络安全隔离**：子网隔离→VLAN隔离→逻辑隔离→物理隔离，**隔离粒度从粗到细，隔离强度和成本同步递增**
- **网络安全协议**：SSL（应用层与TCP/IP间的数据加密/认证/完整性保护）、SET（信用卡支付交易专用）、HTTPS（基于SSL/TLS的HTTP）
- **网络安全审计**：对网络脆弱性的测试评估分析

**与多租户系统设计的同构关系**：隔离粒度的权衡（子网→VLAN→逻辑→物理）与多租户资源隔离级别的权衡（共享库行级隔离→独立schema→独立数据库→独立集群）逻辑相通——隔离越彻底安全性/稳定性越高，但成本和复杂度也越高，需按实际风险等级选择合适粒度，不应无脑上最高隔离级别。

### 5. 交换机技术：STP与VLAN

- **环路问题与STP**：交换机组网用多条物理链路提高可靠性时会产生环路，导致广播风暴等转发异常；**生成树协议（STP）**逻辑上阻塞冗余路径只留一条活跃路径，主链路故障时备份路径自动激活——本质是"主备切换"模式在物理链路层的实现，与服务高可用设计中的"主从+故障自动转移"是同一逻辑：保留冗余资源用于容灾，但同一时刻只有一条活跃路径工作，避免资源同时生效带来冲突
- **VLAN**：把物理网络逻辑划分成多个独立广播域，用于隔离不同用途设备（办公网/应用服务器网段/数据库网段）；纯软件定义隔离，成本低于物理隔离，但隔离强度也弱于物理隔离

### 6. 路由协议选型逻辑（"规模决定技术方案"）

- **内部网关协议(IGP)**：距离矢量协议（简单，只知道到某网络跳数，适合小型网络，但大网络下环路难解决、带宽消耗剧增）vs 链路状态协议（如OSPF，全局拓扑视图，自算最短路径，适合大规模网络）
- **外部网关协议(EGP)**：BGP是现在互联网骨干路由的事实标准

**选型规律**：规模小时简单方案的运维成本优势压倒扩展性缺陷；规模大了简单方案的扩展性缺陷会反过来吃掉运维成本优势——这条规律与服务发现/注册中心选型（小规模用简单心跳广播，大规模需要更复杂的一致性协议或分层服务发现架构）相通。

### 7. 5G服务化架构（SBA）与网络切片（值得作为跨领域印证）

- **服务化架构（Service-based Architecture）**：3GPP在5G核心网引入的架构模式，将核心网拆分成独立的网络功能（AMF/SMF/PCF/NRF等），彼此通过服务化接口互通，用HTTP协议作为承载协议。目标是让网络具备软件快速迭代升级能力，实现灵活定制和按需组合。**电信行业这个传统上极"重"、极封闭的行业基础设施，也走向了服务化架构+HTTP通信，与第14/15章"微服务用HTTP RESTful互调"是同一套思想**——说明服务化架构不是互联网行业专利，而是任何复杂系统应对"需要快速迭代、按需组合"诉求时收敛到的通用架构范式，只是电信行业标准化程度高、变更周期长，走这条路比互联网行业晚了将近十年
- **网络切片**：在单个物理网络上切出多个逻辑网络（eMBB移动宽带/mMTC海量物联网/uRLLC关键任务物联网），针对不同业务场景的差异化需求（带宽/时延/连接数/可靠性）提供定制化服务，避免为每个场景单独建物理网络。本质是"多租户资源隔离+差异化SLA"——与多租户SaaS系统"同一套物理集群，靠命名空间/资源配额/QoS策略服务不同租户"的思路同构，只是网络切片在物理链路和频谱资源层面做这件事

## 二、了解即可（电信工程专业细节，不需要深入记忆）

- **5G具体网元与协议**：AMF（接入移动性管理）、SMF（会话管理）、UPF（用户面功能）、PCF（策略控制）、NRF（网络存储）等网络功能实体，通过N2/N3/N4/N6等接口和HTTP/SCTP/UDP协议通信
- **移动边缘计算（MEC）**：把UPF和计算能力下沉部署到靠近用户的网络边缘，减少时延，支撑低时延业务（如无人驾驶）——本质是CDN边缘节点思想在5G网络的落地
- **5G物理层技术**：OFDM多路复用、大规模MIMO、毫米波频段、LDPC/Polar信道编码——纯通信工程调制编码技术，与软件架构设计无直接关联
- **绿色网络设计原则**：标准化、集成化、虚拟化、智能化，及全生命周期的精简/重用/回收设计——了解"网络设计也要考虑节能环保，架构优化比设备节能影响更大"这个观点即可

## 三、易混淆 / 易错点

1. **层次化网络设计的三层（核心/汇聚/接入）不是按物理位置划分，而是按职责划分**：容易理解成纯粹的物理拓扑分层，实际上核心是"职责单一+细节屏蔽"这套设计原则，物理拓扑只是这套原则的载体
2. **STP解决的是"同时生效"的冲突问题，不是"消除冗余"**：容易误解成STP是为了去掉多余链路，实际上冗余链路依然保留用于容灾，STP只是保证同一时刻只有一条路径处于活跃转发状态
3. **网络安全隔离粒度和成本是正相关的，不是"隔离越强越好"**：容易简单认为物理隔离最安全所以应该优先选择，实际上应该按风险等级和成本预算选择合适粒度
4. **路由协议选型不是"链路状态协议全面优于距离矢量协议"**：容易认为技术更复杂就更好，实际上小规模场景下距离矢量协议的简单易配置优势更重要，协议选型要匹配网络规模
5. **5G网络切片和"虚拟机/容器"不是同一层面的隔离技术**：网络切片是在物理链路和频谱资源层面做的逻辑隔离（涉及FlexE等硬切片技术），不要和计算资源虚拟化技术混淆，两者是"网络资源隔离"与"计算资源隔离"的不同维度
