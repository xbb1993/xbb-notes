# InfluxDB 学习路线图

> 系统学习 InfluxDB 1.x，从"会用"提升到"懂原理、能诊断"；通用原理与实际应用各占一半。
> 版本基线：InfluxDB OSS 1.13.2（生产在用；生产索引为 inmem 与 tsi1 混合）。2.x / 3.x 与其他时序数据库在模块十对比。
> 没有单一教材：大纲由 InfluxDB v1 官方文档、存储引擎与 TSI 设计文档、源码、各产品官方文档等交叉合并而成，详见本地大纲文件。
> 学习方式：每个模块开始前先给三层知识大纲（★ 核心必会 / ☆ 高频重点 / ○ 了解即可）→ 讨论 → 输出笔记。核心专题配实验，关键机制配可交互图解。

## 规模与路径

共 **10 个模块、48 个专题**，其中 ★ 32 个。第一遍走 ★ 主干，☆ 第二遍补齐，○ 按需浏览。

第一遍路径：先过专题 1（☆，全景与入门，紧凑一讲），然后 ★ 主干 2, 3, 4, 5, 6, 8, 9, 11, 12, 14, 15, 16, 17, 18, 19, 20, 21, 24, 25, 27, 28, 29, 30, 31, 32, 33, 39, 40, 43, 45, 46, 47（共 32 个）。

## 与已学内容的关联

| 本主题专题 | 已学内容 | 关联点 |
|---|---|---|
| 8 WAL 与 Cache | Redis AOF、MySQL redo log | 都是"先写日志再确认"，fsync 时机决定丢数据窗口 |
| 11 Snapshot 与 Compaction | Redis RDB 与 AOF 重写 | 都是把内存/日志状态整理成紧凑文件；代价都是 CPU 与 IO |
| 7、16 LSM 与 TSI | MySQL B+ 树 | LSM（追加 + 合并）与 B+ 树（原地更新）的写放大、读放大取舍 |
| 15 inmem 索引 | Redis 内存模型与大 key | 内存随对象数线性增长、重启要重建 |
| 24、31 查询执行与成本 | MySQL EXPLAIN 与索引成本 | 都从"要读多少数据"估算代价；时序库多了时间范围与 shard 维度 |
| 29 迟到与补传 | MQTT t41 断网补传与幂等入库 | 上游补传 → 下游覆盖写与降采样重算 |
| 34 Telegraf 接入 | MQTT t42 规则引擎、t50 接入方案 | MQTT broker 之后的落库环节 |
| 44 高可用 | Redis 复制、Sentinel、Cluster | 副本、分片、最终一致的对照 |
| 47 TimescaleDB | PostgreSQL（生产在用，计划学习） | 在已有 PG 上做时序的可行性与边界 |
