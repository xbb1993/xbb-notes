# 订阅与退订、SUBACK 与重叠订阅

> 专题 9 · 模块二 · ☆ 高频重点 · 第二遍 · 简述（与 13、16、42、49 合讲）
> 非法过滤器断开连接为 Mosquitto 2.0.18 实测（见专题 16）；"退订不删已排队消息"按协议规则整理，未单独实验

**这一章解决什么**：补齐订阅与退订的细节空白，大部分内容前面已覆盖。

## 1. 核心概念

- **一次可订阅多个过滤器**，SUBACK 里每个过滤器单独一个结果：授予的 QoS（0/1/2）或失败码（0x87 无权限、0x8F 过滤器非法）（17）。
- **授予 QoS 可能低于请求**：要 2 只支持 1 就授予 1，按较低者投递。
- **非法过滤器可能导致整条连接被断**：Mosquitto 2.0.18 实测断开（0x81），同一请求里合法的订阅也失效（16）。订阅前在客户端校验过滤器格式更稳妥。
- **重叠订阅**：一条消息匹配同一客户端多个订阅时，Mosquitto 实测投递多份（27），可用订阅标识符区分来源（20）。
- **退订（UNSUBSCRIBE / UNSUBACK）**：取消订阅；已排在会话队列里的消息仍会投递。

## 2. 易混淆 / 易错点

| 错误理解 | 正确理解 |
|---|---|
| SUBACK 成功就是所有过滤器都成功 | 每个过滤器单独结果 |
| 授予的 QoS 就是请求的 QoS | 可能降级 |
| 非法过滤器只影响自己 | Mosquitto 会断开整条连接 |
| 退订后立刻什么都收不到 | 已排队的仍会投递 |

## 4. 诊断实践

| 现象 | 优先怀疑 | 观察点 |
|---|---|---|
| 订阅后连接被断 | 某个过滤器非法 | broker 日志 "Invalid subscription" |
| 收到消息的 QoS 低于预期 | 授予 QoS 降级 | SUBACK 内容 |
| 同一消息处理两次 | 重叠订阅 | 订阅列表、订阅标识符 |
| 退订后仍收到几条 | 会话中已排队的消息 | 退订时间与消息入队时间 |

实验见专题 16 的 `errs.py`（"一次订阅 3 个过滤器，中间一个非法"）。
