# 增强认证、服务端重定向与 3.1.1 → 5.0 迁移

> 专题 21 · 模块四 · ○ 了解即可
> 第二遍 · 低优先级 8 个合讲 · 简述；无实验

## 1. 核心概念

- **增强认证**：5.0 新增 AUTH 报文，客户端与 broker 可多轮"出题、答题"（如挑战应答：服务器给随机数，客户端用密钥签名返回）。用户名密码只能一次性提交，做不到多轮。
- **服务端重定向**：broker 拒绝或断开连接时告诉客户端改连另一台（0x9C 临时、0x9D 永久），可附新地址（17、32）。
- **3.1.1 → 5.0 迁移要点**：Clean Session 拆为 Clean Start + 会话过期时间（12）；新增原因码与属性（17）；CONNACK、PUBACK 等结构变化；broker 一般可同时接受两种版本客户端。
- **用途**：高安全要求的挑战应答认证；broker 迁移扩容时引导客户端；老设备逐步升级。
- **对方案**：若现有电表是 3.1.1，方案要写清新旧混跑过渡期；增强认证与重定向依赖电表库或模组支持（44）。

## 2. 易混淆 / 易错点

| 错误理解 | 正确理解 |
|---|---|
| 用户名密码也能做挑战应答 | 需要 5.0 AUTH 报文的多轮交互 |
| 重定向是负载均衡做的 | 是 broker 在 CONNACK/DISCONNECT 里用原因码告诉客户端 |
| 升级 5.0 要一次性全部替换 | broker 可同时接受 3.1.1 与 5.0，可逐步迁移 |

## 3. 与其他章节的关联

会话（12）、原因码与属性（17）、认证（23）、接入层与重定向（32）、受限设备库支持（44）。

## 4. 诊断实践

| 现象 | 优先怀疑 |
|---|---|
| 迁移后部分设备会话行为变化 | Clean Session 与 Clean Start/会话过期的语义差异 |
| 收到 0x9C/0x9D 后设备不改连 | 客户端库不支持重定向 |
