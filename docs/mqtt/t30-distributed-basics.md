# 分布式通识：CAP、脑裂与复制

> 专题 30 · 模块七 · ☆ 高频重点
> 第二遍 · 低优先级 8 个合讲 · 简述；无实验

## 1. 核心概念

- **一致性与可用性取舍（CAP）**：多台机器间网络断开时只能二选一——暂停服务保证一致，或继续服务接受暂时不一致。
- **脑裂**：集群因网络分成两半，两边都以为对方挂了、各自继续工作，产生互相矛盾的数据。
- **复制**：数据存多份；常见"写到多数副本才算成功"（Raft，31），少数机器坏了不丢。
- **与 MQTT 的关系**：31 的路由表选择最终一致以换取不卡写入；EMQX 持久化会话用 Raft 复制。与已学 Redis Sentinel/Cluster 是同样的取舍。
- **对方案**：用于理解集群 broker 文档、评估"节点故障会丢什么"。

## 2. 易混淆 / 易错点

| 错误理解 | 正确理解 |
|---|---|
| 集群就能同时保证一致和可用 | 网络分区时只能取舍 |
| 多副本一定不丢 | 取决于写多少副本才算成功 |
| 脑裂只是理论问题 | 网络抖动时真实发生，需要仲裁机制 |

## 3. 与其他章节的关联

集群路由与会话（31）、持久化会话 Raft（31）、桥接与多地域（33）、Redis 的复制与 Sentinel（已学主题）。

## 4. 诊断实践

评估集群方案时问三个问题：网络分区时选择一致还是可用？写入需要几个副本确认？如何防脑裂（仲裁）？
