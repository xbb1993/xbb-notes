# 云 IoT 平台与托管服务

> 专题 45 · 模块十 · ○ 了解即可
> 第二遍 · 低优先级 8 个合讲 · 简述；Azure IoT Hub 限制引自微软官方文档（已核实）；AWS IoT Core 除设备影子格式外未逐项核实；无实验

## 1. 核心概念

- **是什么**：用云厂商托管的 IoT 服务（AWS IoT Core、Azure IoT Hub 等）代替自建 broker。
- **最重要：托管服务不一定是完整 MQTT broker**。Azure IoT Hub（官方文档）：
  - 原话"IoT Hub 不是功能完整的 MQTT broker"，需要完整 broker 时官方建议用 Azure Event Grid；
  - 只支持 MQTT 3.1.1（Event Grid 支持 3.1.1 和 5.0）；
  - 不支持 QoS 2：发 QoS 2 直接断开连接，订阅最多授予 QoS 1；
  - 不保存保留消息：带保留标志的消息只加属性转给后端；
  - 8883 端口 MQTT，443 端口 MQTT over WebSocket。
- AWS IoT Core 有设备影子（39 已核实格式）与任务功能，其他限制未逐项核实。
- **对方案**：上云前逐条对照 50 方案用到的功能（5.0 特性、QoS、保留消息——影子方案依赖、共享订阅、遗嘱），不支持的要改方案或换服务。

## 2. 易混淆 / 易错点

| 错误理解 | 正确理解 |
|---|---|
| 云 IoT 服务就是托管的 MQTT broker | 可能只支持部分 MQTT 功能 |
| 保留消息到处都能用 | Azure IoT Hub 不保存保留消息 |
| QoS 2 是通用能力 | Azure IoT Hub 不支持，会断开连接 |

## 4. 诊断实践

| 现象 | 优先怀疑 |
|---|---|
| 发 QoS 2 后连接被断 | 托管服务不支持 QoS 2 |
| 新订阅者拿不到最后状态 | 托管服务不保存保留消息 |
| 5.0 属性不生效 | 托管服务只支持 3.1.1 |
