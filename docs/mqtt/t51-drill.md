### 1.3 半开连接：看不见的断开

道理：路由器清掉空闲连接、或中间链路断了时，**两头都收不到"关闭"通知**，都以为对方还在。只能靠心跳发现：broker 等 1.5 倍心跳，客户端等自己的心跳回应。

实验（心跳 10 秒；连上 2 秒后用 iptables 丢弃这条连接的所有包）：
- broker 约第 16.6 秒发现（1.5 × 10 秒，从最后一次通信算起），发出遗嘱 offline。
- 电表约第 20.5 秒才发现（空闲 10 秒后发心跳，等不到回应）。
- 电表第 21.5 秒就重连成功，而"网络"还没恢复——因为只丢了旧连接那个端口的包，新连接走新端口。这正是 NAT 清掉旧连接的真实情况：**只有旧连接死了，网络本身是通的**。
- 结果：电表只失联十几秒，告警系统却收到一次完整的离线和上线。加遗嘱延迟（如 30 秒）就不会发出这次 offline（15）。

## 2. 易混淆 / 易错点

| 错误理解 | 正确理解 |
|---|---|
| 网络断了两边都会马上知道 | 半开连接两边都不知道，只能靠心跳发现 |
| broker 和设备同时发现断线 | broker 约 1.5 倍心跳；设备要等自己的心跳无回应，通常更晚 |
| 设备能重连说明网络刚恢复 | NAT 只清了旧连接，网络本身一直是通的 |
| 故障只能在线上碰运气遇到 | 绝大多数可以用几种注入手段在本地重演 |
| 仿真只要跑通就行 | 要记录预期、实际与差异原因 |
| 一上来就做集群和压测 | 先确认单机协议行为，再练故障，再压规模，最后端到端 |

### 4.2 脚本（需 root 运行 iptables；本地 Linux + Mosquitto + paho-mqtt）

broker 配置：

```
listener 1883
allow_anonymous true
log_dest file /tmp/t51/b.log
log_timestamp_format %H:%M:%S
```

`halfopen.py`：

```python
# 用 iptables 静默丢包，模拟"路由器悄悄清掉连接"：看 broker 和电表各自多久发现
import paho.mqtt.client as mqtt, time, subprocess, threading
T0=time.time(); ev=[]
def log(s): ev.append(f"  第 {time.time()-T0:5.1f}s  {s}")
mon=mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="monitor", protocol=mqtt.MQTTv5)
mon.on_message=lambda c,u,m: log(f"监控收到 status = {m.payload.decode()}")
mon.connect("127.0.0.1",1883); mon.loop_start(); mon.subscribe("em/meter7/status",1); time.sleep(0.5)
dev=mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="meter7", protocol=mqtt.MQTTv5)
dev.will_set("em/meter7/status","offline",qos=1,retain=True); dev.reconnect_delay_set(1,2)
dev.on_connect=lambda c,u,f,rc,p:(log("电表：连上"), c.publish("em/meter7/status","online",qos=1,retain=True))
dev.on_disconnect=lambda c,u,f,rc,p: log(f"电表：发现连接断了（{rc}）")
dev.connect("127.0.0.1",1883,keepalive=10); dev.loop_start(); time.sleep(2)
port=dev.socket().getsockname()[1]
rules=[["-p","tcp","--sport",str(port),"-j","DROP"],["-p","tcp","--dport",str(port),"-j","DROP"]]
for r in rules: subprocess.run(["iptables","-I","INPUT"]+r)
log(f"开始静默丢弃电表这条连接（本地端口 {port}）的所有包，双方都收不到通知")
time.sleep(25)
for r in rules: subprocess.run(["iptables","-D","INPUT"]+r)
log("恢复网络"); time.sleep(5)
print("\n".join(ev))
```
